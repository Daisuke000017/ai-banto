# AI番頭（えーあい ばんとう）

**ひとりで民泊を回すオーナーの「裏方チーム」を、Claude でつくる。**
宿泊税・年180日・2か月ごとの定期報告・外国語の案内・バスと避難の案内を、AIの係（番頭・経理担当・監査役・宿泊担当）とプログラムが分担して下書きします。確認と提出・送信は、オーナー本人が行います。

- 作った期間：**2026年11月2日〜11月8日**（Built with Claude Japan 2026 のために、この期間に新しく作りました）
- 動かし方・5分で見る順番 → [DEMO.md](DEMO.md)
- 予約・宿泊者・宿は**すべて架空**です。バスの時刻と津波の避難先だけは、実在の公開データです（出典は下にあります）

> English summary: AI Banto is a back-office "team" for solo vacation-rental (minpaku) hosts in Miyazaki, Japan. Claude agents draft guest messages, reconcile payouts and audit each other; plain code does all counting (lodging tax, the 180-night legal cap, bi-monthly reports, bus times, evacuation sites). Built 2026-11-02 to 11-08 with Claude Code. All guest/booking data is fictional.

## 1. だれの、どんな困りごとか

宮崎市の青島で、2部屋の民泊（家主居住型）を1人で営むオーナー（架空の宿「しおさいの家」）を想定しています。

| 困りごと | 中身 |
|---|---|
| 宿泊税が始まった | 宮崎市は **2026年7月1日から1人1泊200円**。民泊も対象で、毎月、人泊を数えて申告する。予約サイトによっては税を集める設定がなく、自分で数えている |
| 年180日の上限 | 住宅宿泊事業法で、1年に泊められるのは180日まで。数え方は「正午〜翌日の正午で1日」「4月1日の正午から1年」と独特で、予約サイトをまたいで数えるのは不安 |
| 2か月ごとの定期報告 | 宿泊日数・人数・延べ人数・国籍ごとの内訳を、予約の台帳から正しく数えて報告する |
| 外国語での案内 | 外国人のゲストには、外国語で設備の使い方や交通・災害時の案内をする必要がある（住宅宿泊事業法 第7条ほか） |
| バスと避難 | 青島は車がないと動きにくく、バスの時刻表は分かりにくい。海の近くなので、津波のときの避難先も伝えたい |

**なぜ今か**（数字はすべて公的な資料で確かめました）

- 宮崎県の民泊（届出住宅）は **1年で約2.3倍**：95件（2025年9月）→ 220件（2026年9月）。全国は +22%。初めての人が一気に増えています（観光庁 住宅宿泊事業の届出状況）
- 宮崎県の外国人の延べ宿泊者数は **26.3万人泊（2025年・前年比 +23.5%）**。伸びている途中で、受け入れの準備が追いついていません（観光庁 宿泊旅行統計調査 2025年確定値）
- 宿泊税は2026年7月に始まったばかりです（総務省 宮崎市宿泊税の新設の同意資料）

日南の民泊オーナーさんに話を聞くと、ゲストの約7割が海外（台湾・ヨーロッパの長期滞在）とのことでした。外国語の案内と、月をまたぐ連泊の数え方は、実際に必要になる場面です。

## 2. 画面と、だれが担当するか

**AIは考える・書く。プログラムは数える・確かめる。** これがこのアプリの芯です。

| 画面 | プログラム（数える・確かめる） | AI（考える・書く） |
|---|---|---|
| 今月の数字 | 売上・手取り・稼働率・客室単価・国籍の内訳（宿泊税は預り金として売上から外す）。経営企画の「値付けの目安」：1泊あたりの手取り（売上−手数料−清掃費）と、180日のペース（埋める優先／高い日に枠を残す） | 使わない |
| 決裁箱の値付けの知らせ | 宮崎の連休・行事の夜で空いている夜（出典つき）を「上げどき」、予約と予約のあいだの1泊だけの空きを知らせ、手取りの目安を出す。「見直した／このまま」を記録して、あとで手取りを比べる。値段を決めて予約サイトに入れるのはオーナー | 使わない |
| 宿泊税 | 人泊 × 200円、月をまたぐ連泊の分け方、預かった額との差 | 使わない |
| 民泊の手続き | 180日のカウンター（残り日数と、上限に届く見込みの月）、定期報告の4項目 | 使わない |
| 清掃が必要な日 | 今日から3週間のチェックアウトの日と「入れ替え」の日、清掃できる時間 | 使わない |
| ゲスト連絡 | 暗証番号・住所・数字の差し込み、訳した文の数字の検査 | 宿泊担当が4か国語で案内を下書き → 別の呼び出しで訳し戻し → 監査役が点検 |
| 予約メール | 書き写した値が本文に本当にあるかの照合、日付の順・泊数・重複の検査 | 番頭がメールから予約の項目を書き写す |
| お金の照合 | 台帳・予約サイトの明細・通帳を突き合わせ、差を計算。候補の理由で差が説明できるか計算で確かめる | 経理担当が明細の列の対応と、ずれの理由の候補を出す → 監査役が疑って差し戻す |
| チームの成績 | 自作の例題40件の採点 | （手元のスクリプトで流した結果を見せるだけ） |
| 訓練：津波注意報 | 宿から近い津波の避難先を距離の順に選ぶ。ゲスト画面を災害モードに | 宿泊担当が泊まっている人ごとの避難の案内を下書き → 監査役が点検 |
| ゲストの画面（QRで開く） | 次のバス・最終バス・1日の本数、近い避難先2つ | 案内係が、ゲストの質問（どこへ行きたいか）を読み取る |
| 予約の台帳 | 手で入れる・直す・取り消す。日付・人数・国籍・金額の検査、同じ部屋の夜の重なりと同じ予約番号の二重登録を止める。日付か人数が変わったらゲスト用URLを止める | 使わない |
| 宿と部屋の設定 | 宿の名前と部屋（A〜Z）の登録。予約が入っている部屋は消さずに「使わない」にする | 使わない |
| 定期報告のCSV | 2か月ごとの定期報告の4項目（宿泊日数・宿泊者数・延べ人数・国籍別）をCSVで書き出す。民泊制度運営システムへ入れるのはオーナー | 使わない |

画面の上には、5人のチーム（番頭・経理担当・監査役・宿泊担当・経営企画）が並び、だれが今どんな仕事をしたか・差し戻したかが見えます。

## 3. AIに数字を書かせないための仕組み

お金・日付・人数・税・バスの時刻・避難先は、**AIには書かせません**。

- **差し込み記号**：AIは `{DOOR_CODE}` `{ADDRESS}` `{GO_DEP}` のような記号を書き、プログラムが正しい値を入れます。使ってよい記号は機能ごとに決め打ちで、たとえば暗証番号の記号は到着案内だけ。ほかの記号が1つでも入っていたら、その答えは捨てて決まった文にします（ゲストの質問から暗証番号を引き出させないため）
- **書き写しの照合**：予約メールでは、AIは本文の文字を写すだけ。写した日付・数字・予約番号が本文に本当にあるかをプログラムが確かめ、無ければ空に戻して「要確認」にします
- **訳し戻し**：訳した文は、日本語の元の文を見せない**別のAI呼び出し**で日本語に戻し、監査役が元と見比べます。訳した文の中の数字・時刻は、プログラムが元の値と突き合わせます
- **監査役**：経理担当の答えや案内の下書きを、別のモデル（Opus）が疑って点検し、根拠が弱ければ差し戻します。差し戻しは2回まで。3回目は「手で確認してください」にします
- **答えの形**：AIの答えは決まった形のJSONだけ。形が違えばプログラムがはじき、1回だけやり直します。AIが答えないときも、決まった文に切り替えて止まりません
- **外から来た文はデータとして渡す**：ゲストの質問・予約メール・明細の文は、区切って「データ」として渡し、中に命令が書かれていても従わないようにしています。名前・電話・メールは、送る前にプログラムが伏せます

## 4. アプリの中での Claude の使い方

### モデルの割り当て（`src/lib/models.js` の1か所だけで変える）

| 係 | モデル | 理由 |
|---|---|---|
| 番頭（予約メールの書き写し） | Claude Sonnet 5.5 | 決まった項目を写すだけ。正しさはプログラムが確かめる |
| 経理担当（列の対応・ずれの理由） | Claude Sonnet 5.5 | 正しさはプログラムが計算で確かめる |
| 宿泊担当（案内の下書き・訳し戻し） | Claude Sonnet 5.5 | 速さと質のつり合い |
| 案内係（ゲストの質問の読み取り） | Claude Sonnet 5.5 | 時刻はプログラムが出すので、AIは文だけ。Haiku にしなかった理由はコードに書いています |
| **監査役**（出す前の最終チェック） | **Claude Opus 5.5** | 疑って確かめる役なので、強いモデルにして見落としを減らす |

### 手引き（Skills）

宿の仕事の勘どころを短い「手引き」にまとめ、AIへの指示の後ろに付けています（`src/lib/skills.js`）。

- **宿の経理の勘どころ**：入金までの日数、振込手数料、キャンセル料と宿泊税、180日の数え方 など（経理担当）
- **宿のおもてなし文例**：ゲストへの返信の書き方（返信の下書きの例題で使用）
- **地名の言いかえ**：ゲストが書いた地名・あだ名を、バスの行き先に読みかえる（案内係）

### 使いすぎ止め

- アプリ全体のAI呼び出しは **1日100回まで**
- ゲストの自由な質問は **1つのURLにつき1日10回まで**（同時に押しても超えないように、1回の更新で数えます）
- 1回の答えの長さにも上限を付けています

## 5. 成績（自作の例題40件）

AIの係が本当に役に立っているかを、**自作の例題40件**（すべて架空）で確かめました。同じ40件を、3つのやり方で流して比べています（`scripts/run-eval.js`、120回、失敗0件）。

| やり方 | 正解 | 止められずに出た間違い | 人の確認へ回した | 余計な差し戻し |
|---|---|---|---|---|
| 手引き＋監査役あり（いまの形） | **38/40** | 2件 | 2件 | 4回 |
| 手引きなし | 37/40 | 2件 | 1件 | 2回 |
| 監査役なし | 37/40 | 3件 | 0件 | 0回 |

- 監査役を外すと、止められずに出る間違いが2件 → 3件に増えました
- 手引きを外すと、民泊の数え方の例題（minpaku-01・02）で間違えました
- いまの形でも、経理の例題2件（keiri-13・keiri-19）は止められずに出ています。監査役は正しい答えを4回差し戻しており、慎重すぎる面もあります。うまくいかなかった例題も、そのまま画面に出しています

例題は自作で、件数も少ないため、これは「この40件では」という結果です。AIの答えも含めた結果そのものは `seed/eval-results.sql` に入れてあり、`npm run db:reset` で「チームの成績」の画面に出ます。

## 6. Claude Code での作り方

このアプリは、**Claude Code を中心に、7日間で作りました**。作り手（私）はエンジニアではありません。

**開発のルールを先に決めた**

## 7. 安全のための決めごと

- **暗証番号はどの表にも保存しません**。`env.DOOR_CODE`（本番では Workers の Secrets）から、コピーや表示のときだけ入れます
- **ゲスト用のURL**：URLの合言葉は、ハッシュ（sha256）だけを保存し、画面に出すのは作ったときの1回だけ。チェックアウトの日の正午で使えなくなり、予約が変わると止まります。使えない理由は、どれでも同じ「使えません」だけを返します
- **宿泊者の名前は読みません**。AIに送る前に、名前・電話・メールなどを伏せます
- 画面は `textContent` だけで作り（`innerHTML` は使わない）、CSP で外のスクリプトを止めています。QRコードも外の部品を使わず自前（`public/qr.js`）です
- **オーナーの画面はログインが必要**です。合言葉はハッシュ（PBKDF2）にして Secrets に置き、ログインの札（Cookie）は12時間で切れます。5回まちがえると15分止まります
- 開けてよい道（ログイン画面・ゲスト画面など）だけを一覧に書き、それ以外はすべて閉じる作りです。合言葉の設定がないまま公開すると、開くのではなく **すべて断ります**
- AIの処理は、米国の Anthropic 社で行います（画面にも表示しています）

## 9. 本番で使う前にやること

まだインターネットには公開していません（手元だけで動きます）。公開する前に、次を行います。

1. オーナーの合言葉を決めて Secrets に置く（`node scripts/hash-password.js` → `wrangler secret put OWNER_PASSWORD_HASH`）。合言葉の計算に時間がかかるため、Workers は有料プランにする
2. セキュリティの点検（特に、ゲスト用URLの確かめ方）
3. 本番のデータベースと、秘密の値（APIキー・暗証番号）を Secrets に置く
4. 本番のデータベースに、新しく足した表（部屋・ログイン）を入れる
5. 公開（`wrangler deploy`）
