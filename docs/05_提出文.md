## プロジェクト名

AI番頭（AI Banto）

## ひとこと

AIは書く、プログラムは数える、決めるのはオーナー。ひとりで民泊を回す人の「裏方チーム」を、Claude でつくる。

## 概要（日本語）

私は地元・宮崎で、事業者をIT・AIで支える仕事をしています。ホテルで働いていたころ、宿は表に見えない裏方の仕事で回っていると知りました。ひとりで民泊を営むオーナーには、その裏方がいません。話を聞いたオーナーは「宿泊税がめんどくさい。AIがないとできていない」と言いました。けれど、AIに数えさせると、税を間違えることがあります。だからAI番頭では、文章はAIが書き、数えるのはプログラム、決めるのはオーナーにしました。

数字をAIに書かせないのには、わけがあります。自作の例題で、AIに宿泊税を数えさせたところ（6月29日から3泊、税は7月1日の夜から）、理由には「400円」と書きながら、答えの欄には「800円」と書きました。AI番頭では金額・日付・暗証番号をプログラムが入れるので、このまちがいは仕組みの上で起きません。AIが書く文章は、別のモデルの監査役（Claude Opus）が疑って点検します。この例でも監査役は答えと理由の食い違いを見つけて差し戻しました。ただ、監査役の言い分も正しくなかったため、3回で決めきらずに「人の確認へ」回しています。AIどうしで決めず、最後は人が決める作りです。

AI番頭のいちばんの見どころは「決裁箱」です。番頭は言われる前に動きます。毎朝7時と、予約メールが届いたときに宿を見回り、やることをカードにして決裁箱に並べます（メールから書き写した予約、4か国語の到着案内の下書き、清掃、180日と定期報告の締切、入金のずれ）。文章はAI（Claude）が書き、お金・日付・人数・宿泊税・暗証番号はプログラムが数えて差し込みます。台帳が変わるのは、オーナーが OK を押したときだけ。送信と提出も、オーナー本人が行います。

背景：宮崎県の民泊は1年で約2.3倍（95件→220件）に増え、宮崎市では2026年7月に宿泊税（1人1泊200円）が始まりました。ひとりで宿を回すオーナーは、毎月の宿泊税の申告、年180日の上限、2か月ごとの定期報告、外国語での案内を、予約サイトをまたいで自分で数えています。

ほかにも、ゲストはQRコードから、自分の言葉で次のバスや「行って戻れるか」、津波の訓練のときの避難先を確かめられます。決裁箱には値付けの知らせも並び、連休や行事の前の空いた夜を「上げどき」として、1泊あたりの手取りの目安と一緒に出します（数えるのはプログラム、値段を決めるのはオーナー）。

自作の例題40件を3つのやり方（いまの形／手引きなし／監査役なし）で流して比べ、うまくいかなかった例もそのまま画面に出しています。テストは260件。Claude Code を中心に、エンジニアではない作り手が7日間で作りました。データはすべて架空です。

これから：もうひとつ心に残ったのは、「高齢の方は申請の手続きが手間で、民泊に興味があっても始めにくい」という声です。始めたあとの事務をAI番頭が引き受ければ、宮崎で宿を始める人を増やせると考えています。宿泊税の率・バスの時刻・避難先を町ごとに入れ替えて、ほかの町や、小さな旅館・簡易宿所にも広げたいと考えています。

## Summary (English)

AI writes, code counts, the host decides. AI Banto gives solo vacation-rental (minpaku) hosts in Miyazaki, Japan, a Claude-powered back-office team.

I work in my hometown of Miyazaki, helping local businesses with IT and AI. When I worked at a hotel, I learned that an inn runs on back-office work guests never see. A host who runs a minpaku alone has no one to do that work. One host I interviewed told me, "Lodging tax is a pain. I can only manage it with AI." But when AI does the counting, it can get the tax wrong. So in AI Banto, AI writes the words, code does the counting, and the host decides.

Why keep numbers away from the AI? On one of our test cases (3 nights from June 29, tax starting the night of July 1), the AI wrote "400 yen" in its reasoning and "800 yen" in the answer field. In AI Banto, amounts, dates and door codes come from code, so this kind of error cannot happen by design. Text the AI writes is challenged by a separate auditor (Claude Opus). In this case the auditor caught the mismatch and sent it back, but its own argument was also wrong, so after three rounds it handed the case to a human instead of deciding. The agents never settle it among themselves; a person does.

The heart of it is the "decision box." The banto acts before it is asked: every morning at 7, and whenever a booking email arrives, it patrols the inn and turns what it finds into cards: bookings read from email, pre-arrival messages drafted in four languages, cleaning, the 180-night and report deadlines, and payout mismatches. Claude writes the words; money, dates, headcounts, lodging tax and door codes are counted and inserted by code. The ledger changes only when the host presses OK, and nothing is sent or filed without the host.

Background: registered minpaku in Miyazaki Prefecture grew 2.3x in a year (95 to 220), and Miyazaki City started a ¥200 per-person-per-night lodging tax in July 2026. Hosts count that tax monthly, stay under the legal 180-night yearly cap, file bi-monthly reports, and guide foreign guests, across several booking sites.

Guests scan a QR code to see the next bus, whether they can get there and back, and tsunami shelters during a drill. The decision box also flags open nights before holidays and local events as chances to raise prices, with the net per night (code counts; the host sets the price).

We ran 40 self-made test cases three ways (current setup, no playbooks, no auditor) and show the failures on screen too. 260 automated tests. Built in 7 days with Claude Code by a non-engineer. All guest data is fictional.

Next: one more thing I heard stayed with me: "Older people are interested in minpaku, but the application paperwork keeps them from starting." If AI Banto takes on the paperwork after opening, more people in Miyazaki may start an inn. We will swap in each town's tax rate, bus times and shelters, and extend it to other towns and to small ryokan and simple lodging houses.

## Claudeをどう使ったか（日本語）

**アプリの中で**
- 5人のAIの係に、仕事に合わせてモデルを分けました。書き写し・下書き・ずれの理由の候補は Claude Sonnet 5.5、出す前の最終チェックをする監査役だけ Claude Opus 5.5 です。割り当ては1つのファイル（`src/lib/models.js`）にまとめ、理由も書いています
- AIの答えは決まった形（JSON）でだけ受け取ります。暗証番号・金額・時刻は記号で書かせ、プログラムが正しい値を差し込みます。訳した文は、元の文を見せない別の呼び出しで日本語に戻し、監査役が見比べます
- 宿の仕事の勘どころ（入金までの日数、宿泊税、180日の数え方など）を短い手引きにまとめ、AIへの指示に足しています
- 効果は、自作の例題40件を「手引き＋監査役あり／手引きなし／監査役なし」の3通りで流して確かめました（120回）

**作るときに（Claude Code）**
- Claude Code を開発の中心に置き、エンジニアではない作り手が7日間で作りました。機能を1つずつ足し、そのたびにテストを足しています（テスト260件）
- `CLAUDE.md` に「鍵や実在の人のデータを入れない」「構成は Cloudflare Workers と D1」「公開は指示があるときだけ」を書き、毎回守らせました。コミットの前には、鍵らしき文字列を探すチェックが自動で走ります（Git のコミット前フック）
- 仕様書は v0 から v1.6 まで直しました。サブエージェントに、品質とセキュリティの審査、数字のファクトチェック（観光庁・総務省などの一次資料との突き合わせ）を分けて頼みました
- 見た目は、作ったセッションとは別のセッションが、4つの画面幅で撮った画面を採点表で審査し、指摘を直して再審査しました（記録は `review/`）
- 実在の民泊オーナー2人に話を聞き、困りごとの順番を入れ替えました

## How we used Claude (English)

**Inside the app**
- Five agent roles, each with a model chosen for the job: Claude Sonnet 5.5 reads booking emails, drafts guest messages and suggests why payouts don't match; only the auditor, which checks everything before it reaches the host, runs on Claude Opus 5.5. The mapping and the reasons live in one file (`src/lib/models.js`).
- Agents answer only in fixed JSON. Door codes, money and times are written as placeholders and filled in by code. Each translation is back-translated by a separate call that never sees the original, and the auditor compares the two.
- Short "playbooks" of host know-how (payout timing, lodging tax, the 180-night rule) are added to the prompts.
- We measured this on 40 self-made cases, run three ways: playbooks + auditor, no playbooks, no auditor (120 runs).

**Building it (Claude Code)**
- Built in 7 days by a non-engineer with Claude Code at the center, one feature at a time, with tests for each (260 tests).
- `CLAUDE.md` sets the rules: no keys or real personal data, Cloudflare Workers + D1 only, no deploy without the owner's go-ahead. A Git pre-commit hook scans for secrets.
- The spec went from v0 to v1.6. Subagents reviewed quality and security and fact-checked every statistic against government sources.
- A separate session scored screenshots at four widths with a rubric; fixes were re-reviewed (`review/`).
- Two real minpaku hosts were interviewed, and their answers reordered the priorities.
