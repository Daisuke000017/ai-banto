## プロジェクト名

AI番頭（AI Banto）

## ひとこと

ひとりで民泊を回すオーナーの「裏方チーム」を、Claude でつくる。

## 概要（日本語）

宮崎県の民泊は1年で約2.3倍（95件→220件）に増え、宮崎市では2026年7月に宿泊税（1人1泊200円）が始まりました。ひとりで宿を回すオーナーは、毎月の宿泊税の申告、年180日の上限、2か月ごとの定期報告、外国語での案内を、予約サイトをまたいで自分で数えています。

AI番頭は、この裏方の仕事をAIの係とプログラムで分けます。AIは考える・書く（予約メールの書き写し、4か国語の案内の下書き、入金のずれの理由の候補）。お金・日付・人数・税・バスの時刻・避難先はAIに書かせず、プログラムが数えて差し込みます。訳した文は別の呼び出しで日本語に戻し、監査役（Claude Opus）が疑って点検し、根拠が弱ければ差し戻します。送信と提出は、オーナー本人だけが行います。

番頭は、言われる前に動きます。毎朝7時と、予約メールが届いたときに宿を見回り、気づいたことを「決裁箱」に並べます（メールから書き写した予約、到着前の案内の下書き、清掃、180日と定期報告の締切、入金のずれ）。見出しと数字はプログラムが作り、台帳が変わるのはオーナーが OK を押したときだけです。予約を OK すると、番頭は次の見回りで到着前の案内を書き、監査役が点検してから、また決裁箱に置きます。番頭が決められないこと（宿泊税の預かり方など）が残る下書きは、OK できません。

ゲストはQRコードから、自分の言葉で次のバスや「行って戻れるか」、津波の訓練のときの避難先を確かめられます。

自作の例題40件で3つのやり方を比べ、監査役を外すと、止められずに出る間違いが2件から3件に増えることを確かめました。うまくいかなかった例もそのまま画面に出しています。テストは196件。Claude Code を中心に、エンジニアではない作り手が7日間で作りました。データはすべて架空です。

## Summary (English)

AI Banto gives solo vacation-rental (minpaku) hosts in Miyazaki, Japan, a Claude-powered back-office team. Registered minpaku in Miyazaki Prefecture grew 2.3x in a year (95 to 220), and Miyazaki City started a ¥200 per-person-per-night lodging tax in July 2026. Hosts must count that tax monthly, stay under the legal 180-night yearly cap, file bi-monthly reports, and guide foreign guests in their language, across several booking sites.

Claude agents think and write: they read booking emails, draft guest messages in four languages, and suggest why a payout doesn't match. Money, dates, headcounts, tax, bus times and evacuation sites are inserted by code, never written by the AI. A separate call back-translates each message, and an auditor agent (Claude Opus) challenges drafts and sends weak ones back. Nothing is sent or filed without the host.

The banto acts before it is asked. Every morning at 7, and whenever a booking email arrives, it patrols the inn and puts what it finds into a "decision box": bookings read from email, pre-arrival message drafts, cleaning, the 180-night and report deadlines, and payout mismatches. Titles and numbers come from code, and the ledger changes only when the host presses OK. Once a booking is approved, the next patrol drafts the pre-arrival message, the auditor checks it, and it goes back into the box. A draft that still holds something only the host can decide (such as how lodging tax is collected) cannot be approved.

Guests scan a QR code to see the next bus, whether they can get there and back, and tsunami shelters during a drill.

On 40 self-made test cases, removing the auditor raised uncaught errors from 2 to 3. 196 automated tests. Built in 7 days with Claude Code by a non-engineer. All guest data is fictional.

## Claudeをどう使ったか（日本語）

**アプリの中で**
- 5人のAIの係に、仕事に合わせてモデルを分けました。書き写し・下書き・ずれの理由の候補は Claude Sonnet 5.5、出す前の最終チェックをする監査役だけ Claude Opus 5.5 です。割り当ては1つのファイル（`src/lib/models.js`）にまとめ、理由も書いています
- AIの答えは決まった形（JSON）でだけ受け取ります。暗証番号・金額・時刻は記号で書かせ、プログラムが正しい値を差し込みます。訳した文は、元の文を見せない別の呼び出しで日本語に戻し、監査役が見比べます
- 宿の仕事の勘どころ（入金までの日数、宿泊税、180日の数え方など）を短い手引きにまとめ、AIへの指示に足しています
- 効果は、自作の例題40件を「手引き＋監査役あり／手引きなし／監査役なし」の3通りで流して確かめました（120回）

**作るときに（Claude Code）**
- Claude Code を開発の中心に置き、エンジニアではない作り手が7日間で作りました。機能を1つずつ足し、そのたびにテストを足しています（テスト196件）
- `CLAUDE.md` に「鍵や実在の人のデータを入れない」「構成は Cloudflare Workers と D1」「公開は指示があるときだけ」を書き、毎回守らせました。コミットの前には、鍵らしき文字列を探すチェックが自動で走ります（Git のコミット前フック）
- 仕様書は v0 から v1.6 まで直しました。サブエージェントに、品質とセキュリティの審査、数字のファクトチェック（観光庁・総務省などの一次資料との突き合わせ）を分けて頼みました
- 見た目は、作ったセッションとは別のセッションが、4つの画面幅で撮った画面を採点表で審査し、指摘を直して再審査しました（記録は `review/`）
- 実在の民泊オーナー2人に話を聞き、困りごとの順番を入れ替えました

## How we used Claude (English)

**Inside the app**
- Five agent roles, each with a model chosen for the job: Claude Sonnet 5.5 reads booking emails, drafts guest messages and suggests why payouts don't match; only the auditor, which checks everything before it reaches the host, runs on Claude Opus 5.5. The mapping and the reasons live in one file (`src/lib/models.js`).
- Agents answer only in fixed JSON. Door codes, money and times are written as placeholders and filled in by code. Each translation is back-translated by a separate call that never sees the original, and the auditor compares the two.
- Short "playbooks" of host know-how (payout timing, lodging tax, the 180-night rule) are added to the prompts.
- We measured this on 40 self-made cases, run three ways: playbooks + auditor, no playbooks, no auditor (120 runs).

**Building it (Claude Code)**
- Built in 7 days by a non-engineer with Claude Code at the center, one feature at a time, with tests for each (196 tests).
- `CLAUDE.md` sets the rules: no keys or real personal data, Cloudflare Workers + D1 only, no deploy without the owner's go-ahead. A Git pre-commit hook scans for secrets.
- The spec went from v0 to v1.6. Subagents reviewed quality and security and fact-checked every statistic against government sources.
- A separate session scored screenshots at four widths with a rubric; fixes were re-reviewed (`review/`).
- Two real minpaku hosts were interviewed, and their answers reordered the priorities.
